생성형 AI에 업무 프롬프트를 입력하기 전 처리방침을 점검할 때

적용 상황: 직원·고객·거래처 정보가 포함될 수 있는 프롬프트를 업무용 AI에 입력하거나 서비스 도입을 검토하는 팀

Must Know · 알아야 할 것

  • 프롬프트는 일회성 질문처럼 보여도 저장·분석·학습·제공되는 구조일 수 있다. 법무팀은 먼저 법적 결론을 내리기보다 실제 데이터 흐름과 공개된 처리방침을 확인한다.
  • 제3자의 정보가 들어갈 수 있으면 입력자 동의만으로 닫히지 않을 수 있으므로, 입력 금지 범위와 예외 승인 절차를 별도로 둔다.

Must Check · 확인할 것

  • 프롬프트와 첨부파일이 저장되는지, 보관 기간과 삭제 방법은 무엇인지 확인한다.
  • 모델 학습·품질 개선·모니터링에 사용되는지, 사용자가 거부하거나 설정을 바꿀 수 있는지 확인한다.
  • 공급자·수탁자·해외 서버 등 제3자 제공 또는 위탁 경로를 확인한다.
  • 이름·연락처·평가·건강·상담 내용처럼 식별 가능성이 있는 입력의 금지 목록을 만든다.
  • 관리자·고객지원·모델 개선 인력의 접근권한과 접근로그 보존 여부를 확인한다.

Must Do · 실행할 것

  1. IT·개인정보 담당자와 함께 입력→저장→처리→삭제 흐름을 한 장으로 그린다.
  2. 처리방침·계약서·관리자 설정 화면을 대조해 서로 다른 설명을 표시한다.
  3. 불일치가 해소될 때까지 개인 식별정보를 입력하지 않도록 사내 안내와 승인자를 지정한다.
  4. 확인 결과를 저장/학습/제공/접근권한 표로 남기고, 변경 시 재검토 일자를 예약한다.
잠깐 멈추고 검토할 때
