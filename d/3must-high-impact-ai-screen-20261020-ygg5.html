우리 AI 서비스가 고영향 AI인지 판단해야 할 때

적용 상황: 채용·신용·의료·교육 등 영역에 AI 기능을 출시하려 하며, 규제상 추가 의무가 붙는지 판단이 필요한 경우. 범위: 법령상 고영향 해당 여부의 최종 판정과 제재 수준은 단정하지 않습니다. 서비스 목록화, 판단 근거 정리, 확인 요청, 의무 이행 체계 정비를 다룹니다.

Must Know · 알아야 할 것

  • "우리 AI는 위험하지 않다"는 자기 평가만으로는 부족합니다. 판단 기준과 근거를 문서로 남겨야 합니다.
  • 판단은 서비스 단위로 합니다. 같은 회사라도 채용용 모델과 내부 문서 요약 모델은 결론이 다릅니다.
  • 결과가 최종 결정을 대신하는지가 중요합니다. 사람이 형식적으로 확인만 하는 구조라면 실질적 개입으로 보기 어렵습니다.
  • 판단이 애매하면 확인을 요청할 수 있습니다. 자체 판단만 하고 확인을 피하면 나중에 불리하게 평가될 수 있습니다.
  • 해당된다고 판단되면 문서화·통지·감독 체계를 서비스 출시 전에 갖춰야 합니다. 출시 후 정비는 비용이 커집니다.

Must Check · 확인할 것

  • 서비스 포트폴리오 전수 목록과 각 서비스의 사용 영역을 정리했는가.
  • AI가 인사·평가·선발·심사 등 중대한 결과를 직접 결정하는가.
  • 사람의 검토가 실제로 결과를 바꿀 수 있는 구조인가, 형식적 승인인가.
  • 사용 데이터에 민감정보·취약계층 관련 정보가 포함되는가.
  • 위험관리·데이터 거버넌스·투명성·인간 감독 중 현재 갖춘 것과 없는 것을 표시했는가.
  • 외부에 공개한 안내문·약관에 AI 사용 사실이 적혀 있는가.
  • 자체 판단서와 확인 요청 필요성 검토 결과를 문서화했는가.

Must Do · 실행할 것

  1. 담당자는 서비스 목록표를 만들고 각 행에 사용 영역 / 결정권 / 영향 대상 / 데이터 유형을 적습니다.
  2. 각 서비스에 대해 해당 가능성 높음 / 낮음 / 판단 보류를 표시하고 근거를 한 줄씩 붙입니다.
  3. 판단 보류 항목은 확인 요청 여부를 결정하고, 요청할 경우 질문과 자료를 정리합니다.
  4. 해당 가능성이 높은 서비스는 의무 항목별 현재 상태와 보완 계획을 표로 만듭니다.
  5. 출시 일정과 보완 계획을 맞춰, 미비 항목이 있으면 출시 범위를 조정합니다.
  6. 판단 결과를 한 장 요약으로 만들어 승인권자에게 보고하고, 판단일·판단자를 기록합니다.
  7. 운영 단계에서 모델·용도가 바뀌면 판단을 다시 하도록 검토 주기를 정합니다.
잠깐 멈추고 검토할 때

인사·신용·의료 등 중대한 영역에서 자동 결정이 이루어지는 경우 · 취약계층이 주된 대상인 서비스인 경우 · 판단이 경계선에 있어 확인 요청 없이 출시하려는 경우 · 이미 출시된 서비스에서 용도가 확장된 경우 · 해외 서비스와 동일 모델을 함께 운영해 다른 규제도 적용되는 경우
