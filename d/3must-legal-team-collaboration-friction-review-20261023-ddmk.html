사업부가 법무팀 검토를 피할 때 협업 장애를 점검할 때

적용 상황: 사업부가 검토 요청을 늦추거나 우회하고, 법무팀과의 협업이 반복적으로 막히는 이유를 팀 차원에서 확인할 때 사용한다.

Must Know · 알아야 할 것

  • “법무팀이 늘 안 된다고 한다”는 평가는 원인이라기보다 확인이 필요한 신호다. 접점별 경험과 실제 처리 흐름을 분리해 살펴본다.
  • 이 카드는 사업부와 법무팀의 협업 절차를 점검한다. 법적 판단의 정답이나 어느 부서의 책임인지는 정하지 않는다.

Must Check · 확인할 것

  • 검토 요청이 늦거나 우회된 사례의 시점·업무 단계·관여자·영향을 식별정보 없이 정리했는가?
  • 요청자가 어렵게 느낀 점(응답 지연, 필요한 자료 불명확, 이유 설명 부족 등)을 직접 수집했는가?
  • 최근 회신에서 결론·이유·추가 확인 항목·담당·다음 시점이 얼마나 명확했는지 살폈는가?
  • 응답 속도와 결과의 질을 뒤섞지 않고 각각 측정할 수 있는가?
  • 개선 과제마다 담당자·시험 기간·확인 지표가 정해졌는가?

Must Do · 실행할 것

  1. 최근 요청 흐름에서 지연·재질문·우회가 있었던 지점을 사실 중심으로 표시한다.
  2. 사업부와 법무팀 양쪽에 익명 또는 비식별 방식으로 요청·회신 과정의 어려움과 도움이 된 경험을 묻는다.
  3. 원인을 요청 단계, 자료 보완, 회신 설명, 승인·결정 대기로 나눠 기록하고 추측은 별도 표시한다.
  4. 우선 개선 한두 가지를 정한다. 예: 요청 서식의 필수항목 안내, 접수 확인, 진행 상태 공유, 회신의 다음 단계 명시.
  5. 정한 기간 뒤 같은 지표와 질문을 다시 확인해 개선 효과와 남은 장애를 기록한다.
잠깐 멈추고 검토할 때

설문이나 사례에 개인·사건·기밀 정보가 포함되어 공유 범위를 정하기 어려운 경우 · 성과 평가가 특정 개인의 책임 추궁으로 바뀌어 조사·인사 이슈와 결합되는 경우 · 단순한 의사소통 문제가 아니라 법률상 의무·기한 판단이 필요한 사례가 드러난 경우
