3MUST · 기업법무

3년 전 표준계약서를 아직도 쓴다는 말을 들었을 때

적용 상황: 현업이 오래된 표준계약서 파일을 그대로 쓰고 있다는 이야기를 들었을 때, 계약서 자동화·템플릿 시스템을 도입했는데 문안 관리가 안 되고 있을 때, 또는 정기 개정 일정이 끊긴 것을 발견했을 때 사용합니다.

Must Know · 알아야 할 것

  • 표준계약서는 완성품이 아니라 관리 대상입니다. 만든 날부터 낡기 시작하고, 점검이 끊기면 "표준"이라는 이름의 위법 조항이 남습니다.
  • 진짜 위험은 조항 하나가 아니라 복제입니다. 표준안이 템플릿·자동화로 쓰이면 오류가 모든 신규 계약에 그대로 증폭됩니다.
  • 버전이 없으면 구버전과 신버전이 뒤섞이고, 사후에 어느 계약이 어느 판인지 확인할 수 없습니다. 분쟁에서 이 점은 그대로 약점이 됩니다.
  • 법령·판례·고시·업계 관행이 바뀌면 조항도 바뀌어야 합니다. 정기 점검 채널이 없으면 변경을 알아채는 것 자체가 불가능합니다.
  • 개정은 조용히 하면 안 됩니다. 상대방에게 적용되는 조항이라면 변경 사실을 알리고 편입 근거를 남겨야 합니다.
  • 자동 생성 문서도 검증 대상입니다. 생성 전 표준안 검증, 생성 후 샘플 검증 두 단계가 모두 필요합니다.
  • 구버전 회수는 공지 한 번으로 끝나지 않습니다. 배포 경로·보관 위치·사용 권한을 함께 정리해야 실제로 멈춥니다.
  • 개정 이력이 없으면 다음 개정도 불가능합니다. 무엇이 왜 바뀌었는지 남기지 않으면 같은 논의를 반복합니다.

Must Check · 확인할 것

  • 표준계약서 전수 목록과 각 문서의 버전·개정일 표시 여부
  • 최근 1년 내 개정 이력이 있는지
  • 현업이 실제로 쓰는 파일이 어느 버전인지
  • 자동화·템플릿 시스템에 들어간 문안이 어느 버전인지
  • 법령·판례·고시 변경을 확인하는 채널과 담당자가 있는지
  • 개정 시 상대방 통지·동의 절차가 정해져 있는지
  • 구버전 회수·사용 금지 통보 방식이 있는지
  • 자동 생성 계약서 샘플 검증 주기가 있는지
  • 개정 권한자와 승인 절차가 문서화되어 있는지
  • 표준안 저장소와 계약 체결 시스템이 연결되어 있는지

Must Do · 실행할 것

  1. 현황 조사. 표준계약서 전수 목록을 만들고 실제 사용 중인 파일과 한 줄씩 대조합니다. 목록 없는 개정은 불가능합니다.
  2. 버전 체계 부여. 주 개정(조항 변경)·부 개정(표현 수정)·오타 수정 3단계 규칙을 정하고, 개정일·담당·사유를 같은 표에 기록합니다.
  3. 변경 감시. 법령·판례·고시·업계 관행을 분기마다 확인하는 달력과 담당자를 지정합니다. 담당 없는 모니터링은 첫 분기에 멈춥니다.
  4. 개정 실행. 조항 단위 변경 내역서를 만들고 승인 절차를 거칩니다. 상대방 통지 문안도 이 단계에서 함께 준비합니다.
  5. 배포·회수. 신버전 배포, 구버전 회수, 사용 금지일 공지를 한 세트로 실행하고 시스템 문안도 교체합니다.
  6. 검증. 자동 생성 문서를 월 1회 샘플 검토하고, 발견된 오류 유형을 기록해 다음 개정에 반영합니다.
  7. 보고. 반기마다 개정 실적과 미개정 목록을 경영진에 보고합니다. 보고가 없으면 일정이 다시 끊깁니다.
