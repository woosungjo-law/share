3MUST · 개인정보·AI법

AI 학습용 데이터에 개인정보가 섞였는지 확인해야 할 때

적용 상황: 개발팀이 웹 크롤링·외부 데이터셋으로 학습데이터를 만들었다고 보고하며 "공개된 데이터라 문제 없다"고 설명하는 경우. 또는 학습 완료 후 데이터 출처를 처음 점검하는 경우. 범위: 개인정보보호법 조문 해석, 위반 성립 여부, 과징금·형사처벌 예상치는 다루지 않습니다. 출처 확인, 처리 근거 선택, 문서화 순서만 정리합니다.

Must Know · 알아야 할 것

  • "공개된 정보"와 "처리해도 되는 정보"는 같은 말이 아닙니다. 공개 여부는 처리 근거를 대신하지 못합니다. 이 한 문장이 이 상황의 출발점입니다.
  • 처리 근거는 하나를 고르는 문제가 아니라 데이터 묶음별로 고르는 문제입니다. 자사 서비스에서 받은 데이터, 크롤링 데이터, 외부에서 산 데이터셋은 근거가 다를 수 있습니다. 한 번에 "전체 정당이익"으로 처리하면 나중에 설명이 무너집니다.
  • 근거 선택은 네 갈래입니다. ① 정보주체 동의, ② 정당한 이익(비교형량 문서화 필요), ③ 가명처리(연구·통계 목적), ④ 익명처리(적용 제외 주장). 익명처리는 재식별 가능성을 스스로 입증해야 하므로 가장 어려운 경로로 봅니다.
  • 비식별·가명처리는 처리 자체를 면제하지 않습니다. 처리 근거가 필요한 대상이 달라질 뿐입니다. "가명처리했으니 괜찮다"는 설명은 그 자체로 검토를 멈추게 만듭니다.
  • 데이터는 수집 → 가공 → 학습 → 출력 단계마다 다른 법역이 걸립니다. 개인정보만 정리하고 끝내면 저작물·이용약관·라이선스 문제가 남습니다. 네 단계를 한 표에 놓고 점검합니다.

Must Check · 확인할 것

  • 학습데이터 목록과 각 데이터의 수집 경로(자체 수집·크롤링·구매·제공받음)를 표로 만들었는가
  • 각 데이터에 개인정보·저작물이 포함될 가능성을 표시했는가
  • 크롤링 대상 사이트의 이용약관·robots.txt 정책과 수집 시점의 준수 여부를 확인했는가
  • 수집 시점에 정보주체에게 고지·동의를 받은 기록이 있는가
  • 가명·익명처리 범위와 재식별 가능성 검토 결과가 문서로 있는가
  • 학습 결과물이 원본 데이터를 그대로 재현하는지 확인할 절차가 있는가
  • 해외 사이트·해외 데이터가 포함되어 역외 규제 검토가 필요한지 확인했는가
  • 처리방침에 AI 학습 목적과 데이터 출처가 실제와 맞게 적혀 있는가

Must Do · 실행할 것

  1. 데이터 담당자와 함께 데이터 묶음 목록을 만듭니다. 묶음 단위는 "출처 + 수집 시점 + 수집 방법"입니다.
  2. 각 묶음을 4분류로 표시합니다: 개인정보 포함 / 저작물 포함 / 둘 다 / 확인 필요. 확인 필요를 남겨두지 말고 담당자와 기한을 지정합니다.
  3. 묶음별 처리 근거 후보를 적고, 근거가 약한 묶음은 학습에서 제외하거나 추가 확보하는 것을 기본 대안으로 검토합니다.
  4. 정당한 이익을 근거로 삼으려면 비교형량 메모(이익의 내용, 최소 처리 범위, 정보주체 권리 침해 정도, 합리적 기대)를 1~2장으로 작성합니다.
  5. 가명처리를 근거로 삼으려면 처리 목적·범위·보관 기간·안전조치를 문서로 남기고, 재식별 금지 조치를 함께 정합니다.
  6. 크롤링 정책을 문서로 확정합니다(대상 사이트 판단 기준, 약관 확인 절차, 수집 기록 보관). 다음 프로젝트부터 이 절차를 통과해야 학습에 들어가도록 합니다.
  7. 처리방침·고지문을 실제 데이터 현황과 맞추고, 개정 시점과 승인자를 기록합니다.
