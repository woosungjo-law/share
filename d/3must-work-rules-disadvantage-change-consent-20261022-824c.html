3MUST · 노동법

취업규칙을 근로자에게 불리하게 바꾸려 할 때

적용 상황: 성과급 기준·휴가·징계·평가 규정 등 취업규칙을 개정하는데, 내용이 근로자에게 불리한 쪽으로 바뀌어 동의 절차를 설계해야 할 때 사용합니다.

Must Know · 알아야 할 것

  • 개정 내용이 합리적인지보다 동의 절차를 제대로 밟았는지가 먼저 문제됩니다. '업계 수준에 맞춘 합리적 변경'이라는 설명만으로는 부족합니다.
  • 불리한 변경이면 근로자 집단의 동의가 필요합니다. 과반수 노동조합이 있으면 그 노조, 없으면 근로자 과반수가 주체입니다.
  • 개별 전자서명을 많이 모으는 방식은 집단적 의사결정으로 인정되기 어렵습니다. 인원수가 아니라 방식이 문제입니다.
  • 동의 과정에 회사가 개입하거나 반대 의견을 제지하면 절차 하자가 됩니다. 진행 방식까지 설계 대상입니다.
  • 근로자가 변경 내용을 검토할 시간이 없었다는 점도 절차 흠이 됩니다. 공지와 설명회 일정을 넉넉히 잡습니다.
  • 회의록·설명자료·질의응답·표결 결과가 남아 있지 않으면 나중에 절차를 입증할 수 없습니다.

Must Check · 확인할 것

  • 개정안 신구대비표와 항목별 불이익 여부 표시
  • 불이익 항목의 적용 대상(전체·특정 직군·신규 입사자)
  • 과반수 노동조합 유무와 교섭 창구
  • 근로자 수 산정 기준과 과반수 계산
  • 설명회 일정과 검토 기간
  • 표결 방식(찬반·무기명·위임 허용 여부)
  • 회사 측 진행자·참관인 구성
  • 기존 근로자에게 적용될 경과 규정(부칙)

Must Do · 실행할 것

  1. 신구대비표를 만들고 불리한 항목을 표시합니다. 표시가 애매한 항목은 따로 모아 판단을 유보합니다.
  2. 동의 주체를 확정합니다. 노조가 있으면 노조와, 없으면 근로자 과반수와 절차를 설계합니다.
  3. 개별 서명 수집 계획이 있으면 집단적 의사결정 절차로 다시 설계합니다. 설명 → 토론 → 표결 순서를 문서로 만듭니다.
  4. 설명자료와 질의응답 목록을 준비합니다. 변경 필요성, 대안 검토 결과, 보완·보상 방안을 함께 담습니다.
  5. 회사가 토론·표결에 개입하지 않도록 진행자 스크립트와 공지문을 정리합니다.
  6. 표결 결과와 참석 현황을 기록하고, 회의록·설명자료와 함께 한 묶음으로 보관합니다.
  7. 절차가 끝나기 전에는 시행일을 확정하지 않습니다. 일정이 촉박하면 시행일을 조정하는 안을 먼저 검토합니다.
  8. 부칙에 시행일과 경과 규정을 넣어, 이미 확정된 권리·의무가 소급해 흔들리지 않게 합니다.
