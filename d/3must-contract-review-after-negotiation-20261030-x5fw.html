계약 검토 요청이 협상 종료 뒤 들어왔을 때 진행기록을 정리할 때

적용 상황: 사업 부서가 상대방과 주요 협의를 마쳤다며 계약서 최종본과 짧은 검토 일정을 법무팀에 전달했을 때 사용합니다. 범위: 어떤 파일이 전달됐고, 어떤 조건을 누가 언제 논의했으며, 무엇이 아직 확인되지 않았는지 기록해 검토 담당자에게 인계하는 절차입니다. 조항의 법적 효력·위험도, 계약 체결 여부, 서명 권한이나 책임은 판단하지 않습니다.

Must Know · 알아야 할 것

  • “협상이 끝났다”는 표현만으로 현재 파일의 버전이나 각 조건의 결정 상태가 확인되지는 않습니다.
  • 초안, 수정본, 비교본, 이메일 합의 기록을 서로 다른 자료로 보존하고, 어느 파일이 현재 검토 대상으로 전달됐는지 표시합니다.
  • 합의·미합의·추가 확인 항목은 결론처럼 단정하지 말고, 해당 기록과 확인한 담당자를 함께 적습니다.
  • 검토 상태와 사업 일정은 실제 진행상태대로 표시합니다. 전달받은 파일을 읽었다는 이유만으로 승인이나 검토 완료로 기록하지 않습니다.

Must Check · 확인할 것

  • 검토 대상 파일의 제목·버전·작성일·전달일과 보낸 사람
  • 직전 버전과 변경표시본, 협상 중 주고받은 문안·이메일·회의 메모
  • 각 쟁점의 현재 문구, 논의 기록, 상태(정리됨·미정·추가 확인 필요)와 확인 담당자
  • 요청된 회신 시점, 예정된 서명·공개·발주 일정과 그 출처
  • 이미 내부 결재나 사업 결정을 받은 항목과 그 기록의 위치
  • 원문 파일의 접근권한·보관 위치와 인계받을 담당자

Must Do · 실행할 것

  1. 전달된 파일을 원본 그대로 보관하고, 파일명·버전·수신 시각을 기록합니다. 검토 중인 사본은 원본과 구분합니다.
  2. 변경표시본이나 협상 기록이 있으면 검토 대상 버전과 나란히 보관합니다. 자료가 없으면 없는 항목과 요청한 사람·날짜를 적습니다.
  3. 쟁점별로 현재 문구 / 논의·결정 기록 / 현재 상태 / 확인 담당자를 한 줄씩 정리합니다. 근거가 없는 항목은 “합의됨”으로 추정하지 않습니다.
  4. 일정·요청 범위·미확인 자료를 별도 목록으로 붙여 검토 담당자와 사업 담당자에게 전달합니다. 급한 일정은 사실대로 적고, 검토 가능 범위나 회신 시점은 담당자가 확인하도록 둡니다.
  5. 검토 의견과 사업 부서의 결정이 오면 해당 버전·결정자·시각·근거 파일을 기록하고, 다음 담당자가 같은 자료를 찾을 수 있는 위치를 남깁니다.
잠깐 멈추고 검토할 때

현재 검토본이 어느 파일인지 서로 다르게 알고 있거나 수정 이력이 누락된 경우 · 결정된 것으로 표시된 문구를 뒷받침하는 기록이 없거나, 회의 메모와 최종본이 다른 경우 · 사업 일정만 있고 검토 범위나 전달 자료가 정해지지 않은 경우 · 대외 공개·서명·발주 등 되돌리기 어려운 일정이 임박했는데 내부 결정 담당자가 확인되지 않은 경우

원자료: 협상 종료 후 법무 검토가 요청되는 가상 업무 사례의 상황 구조만 참고했습니다.

미확인·제한: 법률상 위험·효력·책임·서명 권고는 검토하거나 주장하지 않았습니다. 원문의 가상 인물·기업·금액·결과와 근거가 확인되지 않은 수치·판례 주장은 모두 제외했습니다.
