공공기관이 AI 시스템 도입을 준비할 때

적용 상황: 지방자치단체·공공기관이 민원 처리, 상담, 분류, 예측 등을 위한 AI 시스템 도입을 추진하며 민간 사업자를 선정한 단계. 범위: 영향평가 대상 여부의 최종 판단, 법령 조문 해석, 제재 수위, 위탁·제3자 제공의 법적 성질 판단은 다루지 않습니다. 처리 흐름 정리·기준 대조·계약 요구사항·일정 관리 절차만 정리합니다.

Must Know · 알아야 할 것

  • 사업자를 선정했다는 사실은 개인정보 관련 의무가 끝났다는 뜻이 아닙니다. 의무의 주체는 기관입니다.
  • 어떤 정보가 어떤 목적으로 시스템에 들어가는지를 먼저 그려야 합니다. 이 흐름도가 없으면 이후 모든 검토가 추정이 됩니다.
  • 정보 항목·처리 규모·자동화된 판단 여부·국외 이전 여부는 각각 별도 확인 항목입니다. 하나가 확인됐다고 나머지가 정리되지 않습니다.
  • 수탁사가 평가를 대신 수행하더라도 기관의 확인·감독 책임은 남습니다.
  • 시스템에서 추출한 데이터를 "익명"이라고 부르는 것과 실제로 식별 불가능한 것은 다릅니다. 원본과 결합 가능성이 쟁점이 됩니다.
  • 도입 일정과 평가·계약·검수 일정을 한 표에 놓아야 합니다. 평가가 검수 직전에 몰리면 선택지가 사라집니다.
  • 재수탁 구조가 있으면 계약 조항이 한 단계 더 필요합니다.

Must Check · 확인할 것

  • 시스템이 처리할 개인정보 항목과 처리 목적
  • 예상 처리 정보 주체 수와 보유 기간
  • 자동화된 판단이 정보 주체의 권리에 영향을 주는지 여부
  • 민감정보·취약계층 정보 포함 여부
  • 데이터 보관·처리 서버의 소재와 국외 이전 여부
  • 위탁 범위, 재수탁 여부, 수탁사의 접근 권한
  • 학습·개발에 사용되는 데이터의 출처와 반출 경로
  • 시스템 산출물의 설명·이의제기 창구 설계
  • 기존 개인정보 처리방침·내부 규정과의 정합성
  • 도입 일정, 평가 일정, 계약 체결 일정, 검수 일정

Must Do · 실행할 것

  1. 정보 흐름도를 한 장으로 그립니다. 수집 → 저장 → 처리 → 산출 → 보관·파기 단계마다 담당과 시스템을 표시합니다.
  2. 처리 정보 항목표를 만들고, 각 항목이 어떤 목적에 쓰이는지 연결합니다.
  3. 평가 대상 기준표를 만들어 항목별로 해당·비해당·확인 필요를 표시하고, 판단 근거 문서를 함께 둡니다.
  4. 위탁계약에 필요한 요구사항 목록을 작성합니다. 접근 통제, 재수탁 제한, 반출·파기, 사고 통지, 점검 권한, 산출물 귀속을 항목으로 넣습니다.
  5. 재수탁이 예상되면 승인 절차와 동일 요구사항 적용 조항을 별도로 확인합니다.
  6. 평가·계약·검수 일정표를 역산해 작성하고, 각 단계의 승인권자를 표시합니다.
  7. 도입 전 점검 결과를 내부 결재 문서로 정리합니다. 확인된 사실과 검토가 필요한 쟁점을 분리해 적습니다.
  8. 도입 후 점검 주기와 담당을 정하고, 첫 점검일을 일정표에 넣습니다.
잠깐 멈추고 검토할 때

시스템이 개인의 권리에 직접 영향을 주는 판단을 자동으로 내리는 경우 · 처리 정보 규모가 예상보다 크게 늘어난 경우 · 수탁사가 데이터를 자사 모델 개선에 사용하려는 경우 · 국외 서버·국외 재수탁이 계획에 포함된 경우 · 사업자가 평가를 대신 수행하겠다며 기관의 검토 절차를 생략하자고 제안하는 경우 · 도입 일정이 평가·계약 절차보다 먼저 확정된 경우
