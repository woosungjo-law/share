제품에 오픈소스를 넣기 전에 라이선스를 어떻게 확인할지 정할 때

적용 상황: 제품에 오픈소스를 넣기 전에 라이선스를 어떻게 확인할지 정할 때

Must Know · 알아야 할 것

  • 오픈소스는 조건부로 사용하는 것입니다. 라이선스마다 저작권 표시, 변경 공개, 소스 공개 등 의무가 다릅니다.
  • 라이선스는 크게 강한 카피레프트, 약한 카피레프트, 허용형으로 나눠 봅니다. 분류는 사용 목록의 기준으로 씁니다.
  • 상용 제품에 특정 라이선스 코드를 넣을 때는 법무 검토를 거칩니다. 의무가 제품 전체에 미치는지는 법무가 판단합니다.
  • 사용 목록과 라이선스 기록을 계속 갱신해야 합니다. 버전이 바뀌면 라이선스가 바뀔 수도 있습니다.

Must Check · 확인할 것

  • 제품에 포함된 오픈소스 목록과 버전
  • 각 라이선스의 종류와 원문 파일
  • 제품 배포 형태 (서버 운영, 설치 파일 배포, 임베디드 등)
  • 수정한 오픈소스 코드 여부와 수정 내용 기록
  • 라이선스 호환성 검토 결과
  • 배포 전 자동 검증 도구의 점검 결과

Must Do · 실행할 것

  1. 현재 제품의 오픈소스 사용 목록을 버전과 라이선스 기준으로 만듭니다.
  2. 라이선스를 강한 카피레프트, 약한 카피레프트, 허용형으로 나누고 위험 등급을 표시합니다.
  3. 강한 카피레프트 라이선스가 있으면 제품 구조와 배포 형태를 개발팀과 함께 확인하고, 법무 검토 요청을 올립니다.
  4. 배포 전 점검 단계에 목록 대조와 라이선스 원문 보관 항목을 넣습니다.
  5. 새 오픈소스 도입은 사용 승인 절차를 거치도록 정하고 기록을 남깁니다.
잠깐 멈추고 검토할 때

강한 카피레프트 라이선스가 상용 제품 코드와 결합된 경우 · 라이선스가 명확하지 않거나 원문 파일이 없는 경우 · 오픈소스를 수정해 배포하려는 계획이 있는 경우 · 고객 계약서에서 소스 공개나 보증 조항이 요구되는 경우
