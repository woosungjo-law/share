3MUST · 금융·투자법

감독기관에 금융 민원을 제출하기 전 문안을 점검할 때

적용 상황: 불공정거래·이상거래 정황을 감독기관에 민원으로 제출하려 하며, 민원서에 특정 금융회사명과 거래 내역을 적어야 하는 경우. 범위: 명예훼손 성립 여부, 위법성 조각 판단, 민원의 실질적 결과는 다루지 않습니다. 문안 표현, 근거 데이터, 배포 범위를 점검하는 절차만 정리합니다.

Must Know · 알아야 할 것

  • 같은 사실도 "위법을 저질렀다"고 쓰면 단정이 되고, "이런 거래 흐름이 확인되어 조사가 필요하다"고 쓰면 요청이 됩니다. 이 차이가 문안의 성격을 바꿉니다.
  • 회사명은 거래가 일어난 창구를 가리키는 것과 위법 행위의 주체로 지목하는 것이 다릅니다. 문장 안에서 역할을 분명히 나눕니다.
  • 근거 데이터의 출처와 기준일을 밝혀야 문안이 주장이 아니라 자료 정리가 됩니다.
  • 감독기관 제출용과 언론·외부 공개용은 목적이 다릅니다. 같은 문안을 그대로 쓰지 않습니다.
  • 민원 내용이 외부에 공개될 수 있다는 전제로 작성합니다. 내부 검토 기록도 함께 남깁니다.

Must Check · 확인할 것

  • 문안에 단정·낙인 표현(불법, 사기, 범죄, 조작)이 남아 있는가.
  • 회사명이 등장하는 문장마다 그 회사의 역할이 '거래 창구'인지 '행위 주체'인지 구분되어 있는가.
  • 인용한 거래 데이터의 출처·기준일·산출 방법을 적었는가.
  • 사실과 의견·요청을 문단 단위로 분리했는가.
  • 제출 대상 기관과 배포 범위(내부·기관·언론·SNS)를 정했는가.
  • 외부 공개용으로 쓸 경우 익명화·요약 수준을 정했는가.
  • 민원 제기 사실이 거래·계약 관계에 미칠 영향을 검토했는가.
  • 문안 확정 전 검토자와 승인자를 기록했는가.

Must Do · 실행할 것

  1. 작성자는 민원서 초안에서 단정 표현을 모두 표시하고, 각 문장을 사실 / 의견 / 요청으로 분류합니다.
  2. 분류 결과에 따라 단정 문장을 데이터 제시 + 조사 요청 형태로 고쳐 씁니다.
  3. 거래 데이터 표를 별도 붙임으로 만들고, 출처와 기준일을 표에 적습니다.
  4. 제출용과 공개용 문안을 각각 만들고, 공개용에서는 회사명·개인 식별 정보를 조정합니다.
  5. 법무 검토를 거쳐 표현 수위를 확정하고, 검토자·승인자·확정일을 기록합니다.
  6. 제출 후 기관 회신·보완 요구에 대응할 담당자와 기록 방식을 정합니다.
잠깐 멈추고 검토할 때

민원 대상이 현재 거래 중인 주요 거래처인 경우 · 문안에 내부 임직원·고객의 개인정보가 포함된 경우 · 언론·SNS 동시 배포 계획이 있는 경우 · 이미 다른 기관에 같은 내용이 제출되었거나 조사가 진행 중인 경우 · 문안이 상대방에 대한 협박·압박 수단으로 읽힐 수 있는 경우

원자료: 금융·투자법 EP-003의 위험 신호, 법리 요약, 실무 체크리스트, 실패 패턴

제한: 형법 조문·명예훼손 성립 요건·위법성 조각 판단은 제외했습니다.
