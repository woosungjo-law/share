Must Know · 알아야 할 것

  • 제품 이름이나 직접 설치한 라이브러리만으로는 릴리스 구성 전체를 파악하기 어렵습니다. 빌드에 포함된 전이 의존성, 생성물, 외주 모듈도 목록에 포함할지 개발팀과 정합니다.
  • 구성요소 이름만 기록하지 말고 버전, 출처, 적용 제품·모듈, 받은 조건 문서와 확인 상태를 연결합니다.
  • 조건이 불분명하거나 사용 형태가 바뀐 구성요소는 개발팀이 임의로 통과시키지 말고 법무 검토 항목으로 넘깁니다.
  • 목록과 실제 출시 산출물이 다를 수 있으므로 최종 빌드 기준으로 대조하고, 검토한 버전을 기록합니다.

Must Check · 확인할 것

  • 대상 제품·릴리스 버전·저장소·빌드 기준일이 특정되어 있는가?

  • 각 항목의 이름·버전·출처·제품 내 사용 위치를 확인할 수 있는가?
  • 해당 버전의 라이선스 또는 사용조건 원문과 고지·저작권 문구 자료를 확보했는가?
  • 수정·포크·복사·번들링 여부와 배포 방식이 기록되어 있는가?
  • 외주사나 공급자가 제공한 모듈의 구성요소·조건 자료를 인수했는가?
  • 조건 불명·자료 누락·조합 검토 필요 항목이 별도 예외 목록에 표시되어 있는가?
  • 법무 검토 담당자·질문·회신·승인자·검토 대상 버전이 기록되는가?

Must Do · 실행할 것

  1. 릴리스 범위와 빌드 식별자를 고정하고 개발 책임자와 검토 마감일을 정합니다.
  2. 개발팀에서 구성요소 목록 또는 SBOM을 받아 직접·전이 의존성, 외주 모듈, 생성물을 포함하는지 확인합니다.
  3. 항목별 버전·출처·사용 위치·수정 여부·조건 문서 위치를 채우고, 누락 자료는 담당자와 회수 예정일을 붙입니다.
  4. 현재 출시 형태와 구성요소 조건이 연결되도록 사용·배포 형태 및 고지 자료를 기록합니다. 법률상 허용 여부나 조건 충족 여부는 이 표에서 자체 판정하지 않습니다.
  5. 조건 문서가 없거나 불명확한 항목, 결합·수정·외부 제공이 있는 항목은 질문과 증빙을 묶어 법무 검토로 넘깁니다.
  6. 내부 출시 승인 기준에 따라 필수 검토가 끝나지 않은 예외 항목은 승인 대기 상태로 표시합니다.
  7. 검토 완료 후 승인자·근거 문서·대상 빌드 버전·고지 파일·미해결 예외를 기록하고, 출시 산출물이 바뀌면 해당 항목을 다시 대조합니다.
