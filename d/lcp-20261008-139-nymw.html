법무팀 실무 노트 · 개인정보 국외이전

개인정보 국외이전, 동의보다 먼저 데이터 흐름을 그려라

한 문장. 국외이전 검토는 동의서에 국가명을 하나 적는 것으로 끝나지 않습니다. 고객 데이터가 어느 시스템에서 생성되고, 어느 사업자가 접근하며, 백업과 고객지원 과정에서 어느 국가로 이동하는지를 먼저 그려야 합니다. 결론은 제28조의8과 제28조의9를 기준으로 동의·적정성·계약·보호조치·재위탁을 따로 확인하는 것입니다.

1비유로 먼저 이해하기

수도관을 떠올려 보십시오. 물이 어디서 들어와 어디로 흐르는지 배관 도면 없이 밸브부터 잠그면, 엉뚱한 관을 잠그고 새는 곳은 그대로 둡니다. 데이터 맵은 이 배관 도면입니다. 수집 시스템, 국내 저장소, 해외 수신자, 백업 지역, 고객지원 계정, 하위처리자를 다 그린 다음에야 어느 밸브에 어떤 근거를 붙일지 정할 수 있습니다.

2법이 실제로 보는 지점

첫째, 이전의 근거를 구분합니다. 개인정보보호법 제28조의8과 관련해 개인정보 국외이전의 근거와 조건을 확인합니다. 개인정보보호위원회가 수신국의 보호 수준이 한국과 실질적으로 동등하다고 인정하는 적정성 결정이 있는지, 아니면 동의·계약·다른 법률상 근거를 검토해야 하는지 구분합니다. 적정성 결정이 있다고 해서 모든 처리 목적과 보관기간이 자동으로 적법해지는 것은 아닙니다.

둘째, 보호조치를 계약과 운영에 연결합니다. 제28조의9와 관련해서는 국외이전 과정의 보호조치와 이전 후 관리 절차를 확인합니다. 표준계약, 접근권한 제한, 암호화, 사고 통지, 삭제·반환, 재위탁 통제, 정보주체 문의 창구를 계약과 운영 문서에 연결해야 합니다. 실제 시스템 설정과 계약서가 다르면 서류만으로는 위험을 줄이기 어렵습니다.

셋째, 동의 문구의 구체성입니다. 동의 문구에는 이전 국가, 수신자, 목적, 항목, 보관기간, 거부 시 불이익을 구체적으로 표시합니다. 동의를 받지 않는 다른 근거를 쓰는 경우에는 그 근거와 보호조치를 내부 승인서에 남깁니다. 서비스 약관에 국외이전 문구를 넣었다는 이유로 개인정보 처리방침과 화면 고지를 생략하지 않습니다.

넷째, 검토 패키지와 재검토 시점입니다. 법무팀은 데이터 맵, 공급업체 목록, DPA, 재위탁 목록, 접근 로그, 삭제 증빙을 하나의 검토 패키지로 묶습니다. 해외 서버 위치가 변경되거나 새로운 하위처리자가 추가되면 재검토 시점을 자동으로 발생시키고, 변경 전후의 데이터 흐름을 비교합니다.

3중요한 조건과 예외 — 적정성 결정의 범위를 벗어나면 별도 근거가 필요하다

  • 데이터 맵의 범위 — 단순 저장뿐 아니라 조회·분석·장애 대응을 위해 해외에서 접근하는 경우도 포함합니다.
  • 적정성 결정의 확인 — 결정의 대상 국가·수신자·처리 범위와 회사의 실제 이전 구조가 일치하는지 확인합니다.
  • 범위를 벗어난 재위탁 — 결정의 범위를 벗어나는 재위탁이나 새로운 목적에는 별도 근거와 보호조치가 필요할 수 있습니다.
  • DPA 필수 항목 — 처리 목적, 보안조치, 재위탁 승인, 사고 통지, 정보 반환·삭제, 감사권, 종료 후 확인을 넣습니다.
  • 문서의 동일 버전 — 법무팀은 결정문, 처리방침, 계약서, 시스템 설정을 같은 버전으로 묶어 승인합니다.
  • 정보주체 대응 — 이전 국가와 수신자, 근거, 보호조치, 철회·삭제 절차를 일관되게 안내합니다.
국외이전 적법성 검토와 보안사고 대응은 연결되지만 같은 결론이 아닙니다. 사고가 나면 해외 수신자와 국내 책임자의 연락선, 통지 시점, 로그 보존, 접근 차단, 재발 방지 조치를 순서대로 실행하되, 각각의 담당자와 완료 조건을 나누어 기록하십시오. 사고 대응을 이유로 원본 로그를 삭제하거나 수신자에게 임의로 자료를 회수하지 말고, 조치 시각과 승인자를 남깁니다.

4그래서, 지금 해야 할 일

국외이전 검토는 아래 다섯 항목을 순서대로 확인하는 일입니다. 동의 문구부터 손대면 실제 데이터 흐름과 어긋납니다.

  1. 적용 근거 — 개인정보보호법 제28조의8 적용 근거를 확인합니다.
  2. 보호조치 — 제28조의9 관련 보호조치와 절차를 검토합니다.
  3. 수신자 구조 — 해외 수신자와 재위탁 구조를 확인합니다.
  4. 문구와 흐름의 대조 — 동의 문구와 실제 데이터 흐름을 대조합니다.
  5. 근거의 구분 — 적정성 결정과 계약상 보호조치를 구분합니다.
  6. 사고 대응 훈련 — 사고 시 연락선·통지 시점·로그 보존·접근 차단 순서를 문서로 확인합니다.
