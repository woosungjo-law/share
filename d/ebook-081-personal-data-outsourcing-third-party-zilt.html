개인정보 처리위탁과 제3자 제공 구별 — 위탁과 제공의 경계와 각각의 법적 요건

SECTION

1. 문제상황

"저희 회사는 고객 분석을 위해 외부 데이터 분석 업체에 고객정보를 제공하려 합니다. 위탁 계약을 맺으면 동의가 필요 없다고 들었는데, 맞나요?"

이 질문은 기업 실무에서 가장 빈번하게 발생하는 개인정보 컴플라이언스 질문 중 하나다. 처리위탁과 제3자 제공의 구별은 개인정보보호법 실무의 가장 기본적이면서도 가장 혼동이 많은 영역이다.

구별을 잘못하면 다음과 같은 리스크가 발생한다.

  • 처리위탁으로 계약했지만 실질이 제3자 제공 → 동의 없이 개인정보를 제공한 것으로 간주되어 형사처벌(5년 이하 징역), 과징금(최대 5억 원), 손해배상 책임
  • 제3자 제공으로 동의를 받았지만 사실 처리위탁 → 쓸데없이 행정 부담 증가, 고객 피로도 상승
  • 경계가 모호한 SaaS·API 연동을 사전 검토 없이 진행 → 개인정보위 조사·시정명령 리스크

이 전자책은 대법원 판례가 정립한 구별 기준과 각각의 법적 요건(동의·계약·고지)을 비교형으로 정리하여, 실무자가 현장에서 바로 판단할 수 있도록 돕는다.

2.2 대법원 구별 법리 — 목적·이익 귀속 기준

대법원 2017도13793 판결(2020.3.12.)은 처리위탁과 제3자 제공의 구별 기준을 명확히 정립했다:

개인정보보호법상 "제3자 제공"은 정보를 제공받는 자의 업무처리·이익을 위해 이전되는 경우이고, "처리위탁"은 위탁자 본인의 업무처리·이익을 위해 이전되는 경우로 구별된다.

종합 판단 요소: - 취득 목적·방법: 누구의 목적을 위해 데이터가 이전되는가? - 대가 수수: 수탁자가 독자적 이익을 얻는 구조인가? - 실질적 관리·감독: 위탁자가 통제권을 행사하는가? - 개인정보 보호 필요성: 정보주체의 보호 필요성이 어느 쪽에 있는가? - 실질적 이용 주체: 누가 실질적으로 개인정보를 이용할 필요가 있는가?

핵심 원칙: 계약서 제목("위탁 계약서")이나 형식적 명칭이 아니라, 실질적 데이터 이용 목적과 이익 귀속이 기준이다.

2.3 경계 사례 3-Tier 분류

Tier 분류 예시 판단 기준 필요 조치
Tier 1 처리위탁 확정 IaaS/PaaS (AWS EC2, Azure VM), 단순 인프라, 클라우드 스토리지 위탁자 지시·통제 하 인프라 제공, 데이터 실질적 처리·분석·활용 없음 위탁계약서, 처리방침 고지
Tier 2 판단 필요 SaaS 보조 처리 (Sentry, Cloudflare, Datadog), API 연동, 데이터 분석 용역 독자적 이익 없이 위탁자 서비스 운영·보안 목적에 결박 DPA 체결, 독자 이익 없음 사전 확인
Tier 3 제3자 제공 의심 광고 SDK, 행동분석 후 자체 상품 고도화, 마케팅 제휴사 데이터 제공 제공받는 자의 독자적 처리 목적 존재 별도 동의, DSAR 검토

Tier 2-3 경계가 가장 분쟁 빈발 지대이다. 수탁자의 "부가 서비스 개선"이 실질적 독자 이익에 해당하는지 사전 법률 검토가 필요하다.

3. 각각의 법적 요건

3.1 처리위탁의 요건

위탁 계약 필수 기재사항 (제26조제1항 + 시행령 제28조)

항목 내용
① 목적 외 처리 금지 위탁업무 수행 목적 외 개인정보 처리 금지
② 안전성 확보 조치 접근 제한, 암호화 등 기술적·관리적 보호조치
③ 위탁업무 목적·범위 구체적인 위탁 업무 내용과 범위
④ 재위탁 제한 재위탁 시 사전 승인 필요 명시
⑤ 감독·점검 위탁자의 관리 현황 점검 등 감독 사항
⑥ 손해배상 책임 수탁자 의무 위반 시 손해배상 등 책임

고지 의무: - 일반 위탁: 처리방침에 위탁 업무 내용 + 수탁자 공개 (인터넷 홈페이지 게재) - 홍보·판매권유 위탁: 서면등의 방법으로 개별 고지 + 변경 시 재고지

수탁자 관리 의무: - 수탁자 정기 점검·감독 (연 1회 이상 권장) - 수탁자 교육 의무 - 수탁자 list와 점검 이력 체계적 관리

수탁자의 의무: - 위탁 범위 내 처리 (목적 외 사용 금지 — 제26조제5항) - 재위탁 시 위탁자 사전 승인 (제26조제6항) - 안전성 확보 조치 - 처리 기록 보관

3.2 제3자 제공의 요건

동의 요건 (제17조제2항) — 5대 고지사항:

번호 고지사항
1 개인정보를 제공받는 자 (법인 명칭, 연락처 등)
2 제공받는 자의 개인정보 이용 목적
3 제공하는 개인정보의 항목
4 제공받는 자의 보유 및 이용 기간
5 동의 거부 권리 및 불이익 내용

동의 방식: - 필수 동의와 선택 동의(마케팅 목적 등) 분리 - 선택 동의는 기본값 미체크 (pre-ticked checkbox 금지) - 서면, 전자서명, 체크박스 등 명시적 의사표시 방식 - 동의 철회 방법과 절차 명시

목적 외 사용 제한: - 제공받은 목적 외 사용 금지 - 추가 처리 시 별도 동의 필요 - 제공받은 자는 독자적 처리자로서 책임

3.3 비교표 — 법적 요건 총정리

요건 처리위탁 제3자 제공
정보주체 동의 불필요 필수
계약 문서 위탁 계약 (6대 필수 기재사항) 형식 자유 (단, 동의 시 5대 고지)
처리방침 기재 위탁 내용·수탁자 공개 해당 없음 (동의로 갈음)

5. 위험 신호 — 이 신호가 보이면 즉시 점검

위험 신호 설명 대응
🚩 계약서 제목만 "위탁" 위탁 계약서 형식이지만 수탁자가 데이터를 마케팅·분석·판매에 활용 제3자 제공 해당 여부 즉시 검토, 미동의 시 제공 중단
🚩 수탁자가 데이터로 자체 상품 개발 수탁자가 데이터 분석 결과를 자체 서비스 고도화에 활용 독자적 이익 존재 → 제3자 제공으로 재분류, 별도 동의 필요
🚩 "부가 서비스 개선" 조항 계약서에 수탁자의 부가 서비스 개선 목적 데이터 활용 조항 실질적 독자 이익에 해당하는지 법률 검토
🚩 재위탁 통제 부재 재위탁 금지·제한 조항 없이 수탁자가 임의로 하도급 위탁 계약 하자, 수탁자 관리 의무 위반
🚩 처리방침 위탁 내용 미기재 홈페이지에 위탁 업무 내용·수탁자 미공개 즉시 처리방침 갱신
🚩 수탁자 점검 이력 없음 위탁자가 수탁자 관리 현황을 점검한 기록 없음 연 1회 이상 정기 점검 체계 구축

6. 근거 카드

개인정보보호법 제17조 (개인정보의 제공)

① 개인정보처리자는 다음 각 호의 어느 하나에 해당되는 경우에는 정보주체의 개인정보를 제3자에게 제공할 수 있다. 1. 정보주체의 동의를 받은 경우 2. 제15조제1항제2호·제3호 및 제5호부터 제7호까지에 따라 개인정보를 수집한 목적 범위에서 제공하는 경우

② 제1항제1호에 따른 동의 시 다음 각 호를 정보주체에게 알려야 한다. 1. 제공받는 자 / 2. 이용 목적 / 3. 제공 항목 / 4. 보유·이용 기간 / 5. 동의 거부 권리 및 불이익 내용

개인정보보호법 제26조 (업무위탁에 따른 개인정보의 처리 제한)

① 위탁 시 문서에 포함할 사항: (1) 목적 외 처리 금지 (2) 기술적·관리적 보호조치 (3) 대통령령으로 정한 사항 ② 위탁 업무 내용과 수탁자를 정보주체가 확인할 수 있도록 공개 ③ 홍보·판매권유 위탁 시 개별 고지 (변경 시 재고지) ④ 위탁자의 수탁자 교육·감독 의무 ⑤ 수탁자의 목적 외 이용·제3자 제공 금지 ⑥ 재위탁 시 위탁자 동의 필요 ⑦ 수탁자의 위법 처리 시 손해배상책임 — 수탁자를 위탁자 소속 직원으로 간주 ⑧ 수탁자에 관한 각종 조문 준용

7. FAQ

Q1. SaaS(클라우드 서비스)를 도입하면 처리위탁인가요, 제3자 제공인가요?

SaaS의 성격에 따라 다릅니다. IaaS/PaaS (AWS EC2, Azure VM 등)는 인프라만 제공하므로 처리위탁(Tier 1)입니다. SaaS 보조 도구 (Sentry, Cloudflare 등)는 위탁자 서비스 운영 목적에 결박되어 있으면 처리위탁(Tier 2)이나, 독자적 데이터 활용 가능성이 있다면 주의가 필요합니다. 광고 SDK, 행동분석 도구 등 제공받는 자가 데이터를 자체 목적으로 활용한다면 제3자 제공(Tier 3)에 해당합니다.

Q2. "위탁 계약서"를 작성했는데, 혹시 제3자 제공으로 재평가될 위험은 없나요?

있습니다. 대법원 2017도13793은 형식적 명칭이 아니라 실질적 목적과 이익 귀속을 기준으로 판단한다고 명시했습니다. 제공받는 업체가 데이터를 자체 마케팅, 상품 개발, 고객 분석 등 독자적 목적으로 활용한다면, 계약서 제목이 "위탁 계약서"여도 제3자 제공으로 재평가됩니다. 수탁자의 독자적 이용을 금지하는 조항, 감사권, 파기 의무를 계약서에 명확히 포함하고, 실제 데이터 흐름도 계약과 일치해야 합니다.

Q3. 처리위탁에는 정보주체 동의가 정말 필요 없나요?

네, 처리위탁 자체에 대한 별도 동의는 필요 없습니다. 단, 처리방침에 위탁 업무 내용과 수탁자를 공개해야 하고, 홍보·판매권유 업무 위탁 시에는 개별 고지(서면등의)가 필요합니다. 또한 위탁자가 수탁자를 관리·감독할 의무가 있습니다.

Q4. 마케팅 제휴사에 고객정보를 제공하는 것은 처리위탁인가요, 제3자 제공인가요?

원칙적으로 제3자 제공입니다. 마케팅 제휴사는 제공받은 데이터를 자체 마케팅·분석·타게팅 등 독자적 목적으로 활용하므로, 별도 동의가 필요합니다. 대법원 2016도13263은 보험사가 유통사 고객정보를 사전 필터링한 사안에서, 보험사의 독자적 이익을 인정하여 제3자 제공으로 판단했습니다.

Q5. 제휴사에 최소한의 정보만 전달하는데도 제3자 제공 동의가 필요한가요?

제공하는 정보의 양이 아니라 제공 목적과 제공받는 자의 이용 목적이 기준입니다. 정보량이 적더라도 제공받는 자가 독자적 목적으로 이용한다면 제3자 제공에 해당합니다. 반대로 많은 정보를 전달하더라도 위탁자의 목적 실현을 위한 처리(예: 종합 데이터 분석 용역)라면 처리위탁일 수 있습니다.

Q6. 처리위탁과 제3자 제공을 구별하기 어려운 경우, 어떻게 해야 하나요?

개인정보보호위원회의 유권해석을 신청하거나, 법률 전문가의 검토를 받는 것이 안전합니다. 특히 Tier 2(경계 사례)에 해당하는 SaaS 보조 처리, API 연동, 데이터 분석 용역 등은 사전 법률 검토가 강력히 권장됩니다. 구분이 모호한 경우 보다 엄격한 요건(제3자 제공)을 적용하는 것이 안전한 실무 선택입니다.

Q7. 수탁자가 개인정보를 유출했는데, 위탁자도 책임을 지나요?

네. 개인정보보호법 제26조제7항은 수탁자의 위반으로 인한 손해배상책임에 대해 수탁자를 위탁자 소속 직원으로 본다고 규정합니다. 즉, 위탁자도 사용자 책임을 부담할 수 있습니다. 또한 위탁자가 수탁자 관리·감독 의무를 소홀히 했다면 별도 책임이 추가됩니다.

Q8. 제3자 제공 동의를 받은 후, 제공처가 변경되면 어떻게 하나요?

제공받는 자가 변경되는 경우 변경된 사항을 정보주체에게 알리고 새로운 동의를 받아야 합니다(제17조제2항 단서). 사전에 예상되는 변경 범위를 동의서에 기재하더라도, 실질적으로 다른 업체가 추가된다면 별도 동의가 필요합니다.
