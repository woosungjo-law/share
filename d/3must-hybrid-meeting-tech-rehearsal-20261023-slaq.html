전자·병행 주주총회 전에 접속과 장애 대응을 리허설할 때

적용 상황: 주주총회에서 온라인 참여를 지원하기로 내부 계획을 세운 뒤, 운영·IT·IR 담당자가 플랫폼과 참가자 지원 절차를 점검하는 경우에 사용합니다. 범위: 이 카드는 플랫폼의 기술 준비와 운영 리허설만 다룹니다. 전자·병행 주총의 법적 허용 여부, 정관 요건, 의결권의 효력이나 절차상 하자를 판단하지 않습니다.

Must Know · 알아야 할 것

  • 접속 성공 여부만 보지 말고 참가자가 안내를 받고 접속해 자료를 확인하고 질문을 전달하는 전체 흐름을 시험합니다.
  • 리허설은 실제 안건·실제 표결이 아닌 테스트 자료와 테스트 계정으로 진행하고, 시험 데이터가 실제 기록에 섞이지 않도록 분리합니다.
  • 플랫폼 설정, 참가자 안내, 현장 진행, 기술 지원의 담당자를 나눠 장애가 발생했을 때 누가 기록하고 누구에게 전달하는지 정합니다.
  • 예비 접속 경로와 장애 시 안내 문구는 회사가 승인한 운영계획과 맞춰 점검합니다. 대체 수단이 의결 절차를 바꾸는지에 대한 판단은 법무 검토로 넘깁니다.

Must Check · 확인할 것

  • 초대 링크, 접속 안내, 계정 발급과 문의 채널이 실제 참가자 기준으로 시험되었는가?
  • 본인 확인 단계에서 실패·재시도·담당자 호출 흐름을 테스트했는가? 결과는 기술 오류 기록으로만 남기고 권한 판단과 구분했는가?
  • 현장 진행자, 원격 진행자, IT 지원자, 기록 담당자의 역할과 연락 수단이 지정되었는가?
  • 참가자가 회의 자료를 열고 화면·음성을 확인하며 질문을 제출하는 흐름을 시험했는가?
  • 테스트용 질의와 모의 표결이 실제 안건·실제 집계와 분리되었는가?
  • 접속 끊김, 음성·화면 장애, 자료 미표시, 인증 실패 때 담당자·기록 항목·참가자 안내가 정해졌는가?
  • 승인된 예비 접속 경로와 장애 공지가 준비되어 있고, 사용 조건은 담당 법무가 확인했는가?
  • 미해결 결함마다 책임자, 조치 예정 시점, 재시험 여부가 기록되었는가?

Must Do · 실행할 것

  1. 운영 담당자가 참가자 안내부터 입장, 자료 확인, 질의 제출, 퇴장까지의 흐름도를 만들고 IT·IR·기록 담당자에게 역할을 배정합니다.
  2. 실제 행사와 분리된 테스트 환경에서 초대 링크와 계정, 모바일·PC 접속, 음성·화면, 자료 열람을 순서대로 시험합니다.
  3. 모의 질문과 테스트 표결을 실시해 전달·화면 표시·기록 담당자 간 정보 흐름을 확인하고, 테스트 결과가 실제 회의 기록에 남지 않도록 점검합니다.
  4. 접속 장애 시나리오를 실행합니다. 발생 시각, 영향받은 기능, 참가자 범위, 안내 내용, 복구 시각, 후속 조치를 하나의 로그에 적습니다.
  5. 재시험이 필요한 결함은 담당자와 완료 기준을 지정합니다. 행사 운영안이나 의결 절차에 영향을 줄 수 있는 변경은 담당 법무의 확인 전 확정하지 않습니다.
  6. 행사 당일에는 기술 문의 접수 창구를 하나로 모으고, 진행 책임자에게 장애와 조치 상태를 시간순으로 공유합니다.
  7. 종료 후 시험 로그와 실제 장애 기록을 구분해 승인된 보관 위치에 저장하고 개선 항목을 정리합니다.
