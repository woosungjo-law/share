HTML은 로컬 URL이 아니라 검증된 GitHub URL로 게시한다

HTML 산출물은 브라우저 QA와 실제 공유를 분리한다. 공유가 필요한 경우 GitHub Pages에 게시하고, Pages가 200 OK를 반환한 뒤 원본 노트 frontmatter에 URL을 기록한다.

실제 게시 명령

게시 명령은 실제 HTML과 원본 노트를 함께 지정한다. 스크립트가 Pages 200 OK를 확인한 뒤에만 frontmatter를 수정한다.

powershell -ExecutionPolicy Bypass -File "C:\obsidian\지식관리\_WORKFLOWS\html_pdf_tools\publish_html.ps1" `
  -HtmlPath "C:\obsidian\지식관리\_CREATION\04_시각자료_visuals\20260804_산출물.html" `
  -Slug "20260804-산출물" `
  -FrontmatterPath "C:\obsidian\지식관리\원본노트.md"
완료 기준: 마지막 줄에 PUBLISHED_URL=https://woosungjo-law.github.io/share/d/...가 출력되고, frontmatter와 본문 콜아웃이 같은 검증 URL을 가리킨다.

원본 노트에 남는 값

Frontmatter

web_html: https://woosungjo-law.github.io/share/d/<token>.html
web_html_updated: 2026-08-04
web_html_artifact: d/<token>.html

본문 콜아웃

> [!web] 웹으로 보기
> https://woosungjo-law.github.io/share/d/<token>.html

기존 노트에 dashboard_url이 있으면 같은 검증된 GitHub Pages URL로 갱신한다. Netlify는 GitHub Pages 장애 시에만 보조 필드로 기록한다.

로컬 QA와 게시의 경계

로컬 QA

  • file://가 막힐 때 127.0.0.1 서버를 사용한다.
  • wide/narrow, 콘솔, 키보드, 인쇄 레이아웃을 확인한다.
  • localhost 주소는 공유 URL이나 frontmatter 값이 아니다.

공유 게시

  • publish_html.ps1로 GitHub Pages에 push한다.
  • raw 200과 Pages 200을 모두 확인한다.
  • 가짜 토큰·임의 slug·로컬 경로를 기록하지 않는다.
404 대응: raw 200·Pages 404를 구분하고, Pages가 제한시간 안에 회복되지 않으면 정본 런북에 따라 Netlify fallback을 시도한다. 검증 전 URL은 frontmatter에 넣지 않는다.

작업 전 체크

  • 독자·목적·형식·보존범위·상호작용·배포범위를 먼저 확정한다.
  • 프로젝트 규칙과 Apollo 등 기존 디자인 시스템을 먼저 읽는다.
  • CSS와 핵심 JavaScript는 HTML 안에 넣고, 외부 CDN·원격 폰트·원격 이미지는 사용하지 않는다.
  • 원문 추적성, 모바일 가로 넘침, 접근성, 콘솔 오류, 인쇄 상태를 확인한다.
