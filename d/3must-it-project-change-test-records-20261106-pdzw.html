Must Know · 기준 고정

  • 요구사항은 확인 가능한 기능·입력·결과·예외 단위로 나눕니다.
  • 기존 기준과 변경 요청을 모두 보존합니다.
  • 테스트는 요구사항·산출물 버전에 연결합니다.

Must Check · 변경과 결과

  • 요구사항 ID·기준 버전
  • 요청자·시각·변경 이유
  • 기능·연동·보안 영향
  • 일정·비용 검토와 결정자
  • 적용 버전과 산출물 위치
  • 테스트 기대·실제 결과
  • 결함·재시험 담당

Must Do · 기록 흐름

1

기준 요구사항에 ID를 붙입니다

기능, 입력값, 결과, 예외, 연동 대상을 확인 가능한 단위로 분리합니다.

2

변경 요청과 영향을 기록합니다

기존 기준, 요청 내용, 일정·비용·연동 영향, 결정·담당, 적용 버전을 연결합니다. 검토 중인 요청은 미확정으로 둡니다.

3

산출물 버전별 테스트 결과를 남깁니다

실행 환경, 조건, 기대·실제 결과를 요구사항 ID와 함께 기록합니다. 실패는 결함 ID와 재현 절차로 묶습니다.

4

현재 기준과 미해결 항목을 인계합니다

기준 버전, 승인·보류된 변경, 테스트 상태, 결정할 쟁점을 개발·발주 담당자에게 전달합니다.
