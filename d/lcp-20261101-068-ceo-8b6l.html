AI 심사 결과, 설명하지 못하면 규제 리스크가 됩니다

결론부터. 모델 전체를 공개하라는 것이 아니라 고객이 결과를 이해하고 이의를 제기할 수 있을 정도의 설명이 기준입니다. 설명하지 못하면 규제 리스크가 되므로, 대표가 정할 것은 설명 수준·재심사 절차·모델 거버넌스입니다.

1사건의 시작: 자동 심사 거절 민원이 늘고 있습니다

금융회사의 대표는 자동 신용평가에서 거절된 고객들의 민원이 늘고 있다는 보고를 받습니다. 고객은 이유를 모르겠다고 하고, 모델 담당자는 영업비밀을 이유로 상세 공개를 꺼립니다. 대표가 정해야 할 것은 설명 수준과 재심사 절차, 모델 거버넌스입니다.

2법이 보는 핵심: 설명 요구권과 재산출 요구권이 법에 있습니다

신용정보법 제36조의2는 자동화평가 결과에 대한 설명 요구권, 기초정보의 정정·삭제 요구, 결과 재산출 요구권을 명시적으로 규정합니다.

금융소비자보호법 제19조의 설명의무와 적합성·적정성 원칙도 함께 적용됩니다. 금융 AI의 규범적 프레임은 금융소비자보호법의 설명의무와 신용정보법의 자동화평가 설명·재산출 요구권에서 전개됩니다.

모델 전체를 공개하라는 것이 아니라, 고객이 결과를 이해하고 이의를 제기할 수 있을 정도의 설명을 제공해야 한다는 뜻입니다.

3놓치기 쉬운 조건과 예외: 설명과 보안의 균형을 설계합니다

설명의 범위. 설명의 범위는 고객이 이해할 수 있는 수준이어야 하지만 모델의 영업비밀과 보안을 모두 공개할 필요는 없습니다. 주요 평가 요소와 거절 사유의 범주를 설명하는 방식이 일반적입니다.

정정과 재산출. 기초정보 오류가 확인되면 정정 후 재산출 절차를 거쳐야 하고 그 과정을 기록해야 합니다. 기초정보 정정 요구가 들어오면 출처와 갱신 절차를 확인하고, 정정 결과를 반영해 재산출하는 절차를 거쳐야 합니다.

내부통제. 평가 기준의 합리성과 차별적 요소 개입 여부도 내부통제 관점에서 점검해야 합니다. 오탐은 민원을 늘리고 미탐지는 손해배상 문제를 부르므로 정기적으로 점검하십시오.

문서화와 이력. 설명 요구에 대응하려면 입력 변수와 주요 판단 기준을 문서화해 두어야 합니다. 모든 변수를 공개할 필요는 없지만 어떤 정보가 불리하게 작용했는지 범주 수준에서 설명할 수 있어야 하고, 모델이나 데이터가 바뀌면 설명 내용도 달라지므로 변경 이력을 관리하십시오.

외부 모델과 처리 기록. 외부 업체 모델을 쓰는 경우에는 설명 자료 제공 의무와 책임 소재를 계약에 명확히 해야 합니다. 요구 유형별 처리 기간을 관리하면 병목을 찾을 수 있고, 반복 민원에는 담당자를 지정해 일관되게 대응하며 처리 기록을 남겨 분쟁조정에 대비하십시오.

비용과 중단 기준. 비용은 설명 체계 구축과 민원 대응 비용, 규제 대응 비용을 함께 계산하고, 중단 기준은 설명이 불가능한 모델을 계속 사용하는 시점입니다.

주의. 설명이 어려운 모델은 도입을 서두르지 말고, 설명 가능한 범위에서 운영하는 편이 안전합니다. 모델 담당자와 법무, 고객센터가 같은 기준으로 답변하도록 교육하십시오.

4그래서, 대표가 정할 것

설명 체계와 거버넌스를 정하십시오. 정할 항목은 다음과 같습니다.

  1. ① 기준 정리 — 평가 기준과 데이터 출처를 정리하게 합니다.
  2. ② 설명 수준 — 고객에게 제공할 설명 수준을 정합니다.
  3. ③ 정정·재산출 — 정정·재산출 절차와 담당자를 지정합니다.
  4. ④ 이력 관리 — 모델 변경 이력을 관리합니다.
  5. ⑤ 민원 반영 — 민원 사례를 기준 개선에 반영합니다.
  6. ⑥ 교육 — 의사결정 기록에 설명 체계 구축 비용과 규제 리스크를 함께 적고, 부서 간 답변 기준을 맞춥니다.

설명 가능성은 규제 대응이면서 동시에 고객 신뢰의 문제입니다. 설명 처리 결과를 고객에게 이해하기 쉽게 통지하고, 재산출 결과의 변화도 알려 주십시오. 설명 범위와 처리 기준은 정기 점검을 거쳐 갱신하십시오.
