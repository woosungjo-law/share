창작컴파일러 사용방법 — 한 장 총정리

이 폴더가 무엇이고, 어떻게 여기까지 왔고, 결과물이 어디에 쌓이며, 어떻게 잘 쓰는지를 한 번에 잡는다.

원본 노트: 70_lab/사용방법_20261017.md · 정문 [[_주문서]] · 구역 [[_구역안내]] · 건강 [[_계기판]] · 규칙 [[CLAUDE]] v3 · 갱신 2026-10-17

이 WIKI는 글 창고가 아니라 “재료 팬트리 + 밀키트 저장고”다.  재료는 미리 풍부하게, 요리는 주문이 올 때.

0한 줄 정체성

컬럼을 부담 없이 드롭하면 → 심층 분석 + 웹보강을 거쳐 재료(재사용 조각)가 되고 → 서로 합성해 밀키트(반조리 시리즈 설계)가 되고 → 주문이 오면 _ATELIER에서 요리(초안)한다.

재료는 미리 풍부하게, 요리는 주문이 올 때.  성공의 정의 = 요구가 오면 몇 시간 안에 좋은 초안이 나온다.

핵심 규칙 3줄

  1. 정본 소스는 원래 위치에 그대로 둔다. 이 WIKI는 복제 저장소가 아니라 포인터 + 추출 재료 + 변형 설계를 관리한다.
  2. 기본 단위는 “글 1편”이 아니라 재료(Module) / 패턴(Pattern) / 소스팩(Source Pack) / 밀키트(Meal-kit)다.
  3. 목표는 축적이 아니라 같은 재료로 여러 톤·독자용 결과물을 반복 생산하는 것이다.

1정확한 기능 — 두 개의 문 + 3구역

🚪 문 ① 재료 투입 (공급 · 자유)

1. 00_raw/에 컬럼을 드롭

2. “창작컴파일러 재료로 인제스트해줘” → SPACK 편입 → 재료 추출(프레임·비유·사례·데이터·질문·오프닝·결론·반론) → 필요 시 웹보강 → 교차 가능하면 밀키트 후보 제안

3. 원문은 00_raw_ingested/로 이동(보관)

🍳 문 ② 요리 주문 (수요 · 온디맨드)

1. [[_주문서]]에서 밀키트를 고르거나 주제만 적는다

2. “[주제/밀키트]로 [플랫폼] 초안 만들어줘” → 재료·밀키트 자동 소집 → 실물 초안 저장

3. 이 WIKI엔 50_outputs/에 포인터만 남는다

🥫🍱🍽 3구역 모델

구역폴더역할
🥫 팬트리(재료)10_source_packs/SPACK — 주제별 재료지도(재료 선반)
20_modules/재료(Ingredient) — 유형·등급·검증 메타. 프레임/소재 2계층
30_patterns/패턴 — 재료의 ‘전개유형’
60_tones/톤 — 조미료 층
🍱 밀키트40_mealkits/KIT — 신규 밀키트(단일/크로스). 크로스가 이 WIKI의 꽃
40_compile_notes/COMP — 레거시 밀키트(점진 이관)
🍽 출력50_outputs/OUT — 완성본 포인터 + 변형 이력(정본은 _ATELIER/허브)
🗄 보관·운영00_raw/ · 00_raw_ingested/ · 70_lab/ · 80_templates/드롭존 · 원문보관 · 실험로그 · 템플릿

재료 유형 — 프레임 · 비유 · 사례 · 데이터 · 질문 · 오프닝 · 결론 · 전개패턴 · 반론(counter) …
재료 등급 — 원석(추출만) → 가공(웹보강·정제) → 밀키트급(앵커). verified = 실제 출력에 쓰여 검증됨.

⚙ 자동 장부 (손 관리 금지)

자산을 더하거나 요리한 뒤 폴더 루트에서 한 줄이면 카운트·등급·검증·status가 전부 자동 갱신된다.

cd C:\obsidian\지식관리\_WIKI_창작컴파일러
python _index_generator.py
모든 _index.md · index.md 카운트 · _계기판 · 등급 · verified · status가 자동 생성된다. 인덱스를 손으로 고치지 않는다.

3결과물이 어디에 모여 있나

① 재료·밀키트 자산 (이 폴더 안)

  • 재료: _WIKI_창작컴파일러/20_modules/ (약 1,440+)
  • SPACK 선반: 10_source_packs/ (약 390)
  • 밀키트: 40_mealkits/ (KIT 300) + 40_compile_notes/ (COMP 11)
  • 패턴·톤: 30_patterns/ · 60_tones/
  • 출력 포인터: 50_outputs/ (약 403개)
  • 상태·이력: _계기판.md · log.md · _cc_ledger.jsonl(정본 원장) · _batch_manifest.md · 70_lab/

② 실제 완성 컬럼(초안 정본) — 이 폴더 밖

문②로 요리한 1,500자 컬럼 실물은 여기 쌓인다.

_WIKI_인문비즈니스/90_archive/column/04_창작컴파일러/1500자컬럼/{클러스터}/
  • 클러스터(주제 폴더) 예: 인재와평가 · 돈과계약 · 협상과교착 · 침묵과경청 · 평정심과선택 · 퇴장과끝맺음 · 칭찬과인정 · 판단과질문 등 13개 + _미분류/
  • 현재 약 784편+ 실물 저장. status: draft
  • 50_outputs/OUT-*.md 파일이 그 실물을 가리키는 포인터다.
즉, “뭘 만들었나”는 50_outputs/_index.md와 1500자컬럼/ 폴더에서 본다. 이 WIKI 안에는 완성 원고를 복제 저장하지 않는다.

4이걸 어떻게 잘 활용하나

원칙 4가지

  1. 시작은 언제나 [[_주문서]]. 재료를 넣든 요리를 시키든.
  2. 요리는 이 폴더에서 하지 않는다. 여기엔 재료·밀키트·포인터만.
  3. 작업 뒤 스크립트 한 줄이 마감. python _index_generator.py
  4. 부피가 아니라 [[_계기판]]으로 평가. 다양성·재사용률·교차율.

루틴 A · 새 재료가 생겼을 때 (문①)

00_raw에 드롭 후 — “창작컴파일러 재료로 인제스트해줘. 유형(비유·사례·데이터·질문·반론)도 다양하게, 사실은 웹보강, 교차 가능성 보이면 밀키트 후보까지.”

루틴 B · 글이 필요할 때 (문②)

“[밀키트명 또는 주제]로 [플랫폼] 초안을 써줘.”
예: “교착 밀키트로 경영컬럼 EP01 초안 써줘”

루틴 C · 글감이 막힐 때

[[_계기판]]과 40_mealkits/_index를 열어 아직 요리 안 한 밀키트를 고른다.

루틴 D · 새 시리즈 (크로스가 꽃)

“서로 다른 SPACK의 재료를 교차해 [주제] 크로스 밀키트를 만들어줘.” 공통 질문 하나로 여러 재료를 꿴다.

6한 줄 결론

이 폴더를 잘 쓴다는 것은 재료를 많이 넣는 것이 아니라, 유형별로 잘 차려두고(팬트리) 미리 조합해(밀키트) 두었다가, 주문이 오면 빠르게 요리(초안)하는 흐름을 도는 것이다. 그 흐름의 건강은 [[_계기판]]이 알려주고, 장부는 스크립트가 지킨다. 사람은 무엇을 낼지 정하고, 요리하면 된다.
