업계 공용 가격 알고리즘 도입을 검토할 때

적용 상황: 사업전략·영업팀이 업계 공용 가격최적화 솔루션 또는 경쟁사와 같은 벤더의 가격책정 툴 도입을 검토하며 법무팀에 사전 검토를 요청한 경우. 범위: 담합 성립 여부, 의사연락의 상호성 판단, 공정거래법 조문·판례, 과징금 산정은 다루지 않습니다. 데이터 입력 경로 확인·계약 조항 점검·기록 관리·사전 검토 문서화 절차만 정리합니다.

Must Know · 알아야 할 것

  • 알고리즘이 가격을 올렸다는 결과만으로 문제가 성립하는 것은 아닙니다. 다만 조사는 결과가 아니라 사람 사이의 접촉과 데이터 흐름을 봅니다.
  • "우리가 직접 합의한 적은 없다"는 답변은 방어가 되지 않습니다. 어떤 정보가 어떤 경로로 들어갔는지가 먼저 정리되어야 합니다.
  • 경쟁사의 비공개 가격·전략 정보가 시스템에 들어가는 구조라면, 도입 시점에 이미 설명 부담이 생깁니다.
  • 벤더가 여러 사업자에게 같은 대시보드를 제공하는 구조는 그 자체로 확인 대상입니다. 데이터 제공 범위를 계약서에서 확인해야 합니다.
  • 도입 후에는 데이터 소스를 바꾸기 어렵습니다. 도입 전에 입력 명세를 문서로 고정해야 합니다.
  • 가격 변경 이력과 의사결정 기록이 남아 있어야 나중에 설명이 가능합니다. 자동 변경이라고 해서 기록이 없으면 곤란해집니다.
  • 사업부가 "업계에서 다 쓴다"고 말할 때, 그 사실 자체가 검토 사유입니다.

Must Check · 확인할 것

  • 시스템에 입력되는 데이터 소스 목록과 각 소스의 공개·비공개 여부
  • 경쟁사 가격·전략 데이터 포함 여부와 유입 경로
  • 벤더와의 계약서 중 데이터 제공·공유·재판매 조항
  • 공용 대시보드·벤치마크 기능의 제공 범위
  • 가격 변경 규칙(누가, 어떤 조건에서 승인하는지)
  • 가격 변경 이력의 보관 주기와 담당
  • 도입 전후 사업부·벤더와의 커뮤니케이션 기록
  • 경쟁사와의 접촉 이력(회의·제휴·협의회)
  • 시스템 운영 담당자와 의사결정 라인
  • 도입 검토 결과를 보고할 내부 창구

Must Do · 실행할 것

  1. 입력 데이터 명세서를 작성합니다. 소스명·제공자·공개 여부·갱신 주기·활용 목적을 열로 둡니다.
  2. 벤더 계약서에서 데이터 관련 조항을 발췌해 조항 대조표를 만듭니다. 제공·공유·재판매·익명화·감사 조항을 항목으로 둡니다.
  3. 경쟁사 정보가 들어올 수 있는 경로를 도식으로 그립니다. 직접 입력·벤더 경유·업계 제휴·공용 대시보드로 구분합니다.
  4. 가격 변경 승인 절차를 문서화합니다. 자동 변경과 수동 개입 지점을 구분해 표시합니다.
  5. 도입 전 검토 의견서를 작성합니다. 확인된 사실, 확인이 필요한 항목, 권고 조치를 분리합니다.
  6. 계약 협상 시 경쟁 정보 차단 조항과 데이터 감사 조항을 요구 목록에 넣습니다.
  7. 도입 후 점검 일정을 정합니다. 입력 데이터 변경 시 재검토 조건을 문서에 명시합니다.
  8. 사업부에 검토 결과와 기록 보관 의무를 서면으로 전달합니다.
잠깐 멈추고 검토할 때

벤더가 경쟁사 가격 정보를 대시보드로 제공하는 경우 · 사업부가 업계 협의회에서 가격·물량 정보를 교환한 정황이 있는 경우 · 가격 변경이 경쟁사와 같은 날짜에 반복적으로 일치하는 경우 · 도입을 서두르자는 요구와 함께 검토 기록을 남기지 말자는 제안이 있는 경우 · 공정위 조사가 이미 진행 중이거나 관련 문의를 받은 경우 · 그룹 계열사가 같은 벤더 솔루션을 공유하는 경우
