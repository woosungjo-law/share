법무팀 · ELI5 실무 안내 · LCP-20260930-196

자동승인이면 사람이 책임지지 않는다는 통념이 아닌, 개입 기록이 형사 쟁점을 가른다

한 문장으로 먼저 말하면
승인이 자동으로 처리됐다는 사실만으로 형사 쟁점이 사라지는 것은 아니다. 확인·승인·송금에 사람이 개입한 흔적이 있으면 형법 제347조 사기죄와 제347조의2 컴퓨터등사용사기죄 중 어느 쪽으로 다투게 되는지가 개입 기록에 따라 갈린다.

1사건의 시작

비유하면 이렇습니다. 자동문이 열어 줬어도, 문 앞에서 누군가 버튼을 누르거나 잠금을 풀었다면 '문이 혼자 열렸다'고 말하기 어렵습니다. 시스템이 처리한 일과 사람의 손이 닿은 지점을 기록으로 분리하는 것이 형사 쟁점을 가르는 첫 출발점입니다.

컴퓨터 승인 뒤에 남은 직원의 손
핀테크 회사 윤슬페이의 법무 담당 표윤재는 비대면 대출 사건의 로그를 검토했습니다. 신청서 접수와 한도 산정은 자동으로 처리되었지만, 예외 승인 화면에는 직원의 계정과 메모가 남아 있었고 송금 직전에도 수동 확인이 있었습니다. 사업팀은 컴퓨터가 승인했으니 사람의 사기죄 문제는 없다고 설명했습니다. 표윤재는 자동화라는 이름을 결론으로 쓰지 않고, 고객 정보가 어떻게 입력되었고 누가 확인·승인·송금에 관여했는지를 시간순으로 다시 만들었습니다. 관련 자료는 신청 데이터, 본인확인 결과, 예외 처리 규칙, 직원 로그인, 승인 버튼 기록, 송금 지시와 계좌 내역으로 나누었습니다. 프로그램의 정상 작동과 특정 직원의 개입은 서로 다른 층위이므로, 시스템 설명서 하나만으로 형사 쟁점을 판단하지 않기로 했습니다.

2법이 실제로 보는 지점

기망의 상대와 처리 방식이 다르다
형법 제347조 사기죄의 성립요건인 기망행위는 사람으로 하여금 착오를 일으키게 하는 것을 말합니다. 법무팀은 누가 어떤 정보를 누구에게 제시했고, 그 정보가 사람의 판단에 영향을 주었는지 자료로 확인해야 합니다. 자동 심사라는 문구만으로 기망 여부가 사라지거나 바로 확정되는 것은 아닙니다. 사람의 개입이 확인되면 형법 제347조의2의 컴퓨터등사용사기죄나 사기죄 성립 여부를 다시 검토할 수 있습니다. 검찰은 자동심사라도 직원의 확인·승인·송금 개입 여부와 형법 제347조의2 적용 가능성을 확인해야 합니다. 법무팀은 수사기관의 결론을 대신하지 않고, 입력·변경·승인·송금 로그가 어떤 사실을 보여주는지 정확히 설명하는 역할을 해야 합니다.

3조건과 예외

로그를 지우지 말고 역할을 나눈다
첫째, 신청자가 제출한 정보와 시스템이 자동으로 산출한 결과를 구분합니다. 둘째, 예외 규칙을 적용한 사람과 적용 이유를 확인합니다. 셋째, 승인 후 송금까지 누가 어떤 화면을 조작했는지 기록합니다. 형법 제347조의 사람에 대한 기망과 제347조의2의 컴퓨터등사용사기 검토가 어느 자료에 연결되는지 별도 표를 만듭니다. 수사나 내부 조사가 시작되면 로그를 정상 데이터와 별도로 복사해 원본 해시·보존일·접근자를 기록합니다. 직원이 고객 정보를 수정했더라도 수정 사실을 숨기기 위해 원본을 덮어쓰지 않습니다. "자동이었다"거나 "직원이 처리했다"는 단정은 실제 기록과 맞을 때만 보고서에 넣고, 확인되지 않은 부분은 미확인으로 표시해야 합니다. 검찰이 확인해야 할 직원의 개입은 단순히 로그인했다는 사실과 같지 않을 수 있습니다. 어떤 정보를 알고 있었는지, 승인 버튼을 눌렀는지, 송금에 영향을 주었는지, 시스템이 정한 절차에서 벗어났는지를 각각 나눠야 합니다. 법무팀은 형법 제347조의2 적용 가능성을 말할 때도 판례번호나 외부 결론을 임의로 추가하지 않고 KIT의 조문과 실제 로그를 연결합니다. 대출 신청자에게 허위 정보를 알린 사람이 회사 내부인지 외부 대행사인지도 역할표에 구분합니다. 직원이 승인 화면을 열었지만 실제 값을 바꾸지 않았는지, 반대로 자동 결과를 사람이 수정하고 송금 지시까지 했는지 로그와 업무 매뉴얼을 대조해야 합니다. 수사기관에 제출할 때에는 시스템 설명서, 로그 원본, 로그를 읽는 방법, 보존 절차를 한 묶음으로 만들고 원본과 분석본을 구분합니다. 직원 인터뷰 내용은 로그를 대신하지 않으며, 인터뷰로 새 사실이 나오면 원자료와 별도 진술 기록으로 저장합니다. 권한표와 실제 로그가 다르면 어느 쪽이 맞는지 추측하지 말고 시스템 관리자에게 원본과 생성 방식을 확인받고, 차이를 확인한 시각과 확인자를 남깁니다. 자동화 모델의 업데이트 버전과 배포 승인도 로그와 함께 묶습니다. 같은 신청이 어떤 버전에서 처리되었는지 재현할 수 있어야 합니다.

4그래서, 지금 해야 할 일

자동화와 사람의 개입을 한 장에 그린다
표윤재는 사건 흐름도를 입력·심사·예외승인·송금 단계로 나누고, 각 단계에 시스템·직원·외부기관의 역할을 적었습니다. 형법 제347조의 기망행위 검토 자료와 제347조의2의 컴퓨터 처리·직원 개입 자료를 분리해 보관하고, 검찰이 확인할 수 있는 로그 목록을 만들었습니다. 형사책임을 미리 선언하는 대신 사실의 순서를 보존하는 것이 첫 대응입니다.

✓법무팀 체크포인트

  • ① 입력 보존: 형법 제347조와 관련해 신청 정보·제출자·변경 이력을 원본으로 보관합니다.
  • ② 사람 구분: 제347조의2와 관련해 확인·승인·송금에 개입한 계정을 분리합니다.
  • ③ 로그 보존: 자동 규칙·예외 규칙·수동 조작의 시간과 담당자를 고정합니다.
  • ④ 보고 절제: 확인된 사실과 형사적 평가가 필요한 부분을 구분해 설명합니다.
  • ⑤ 접근 통제: 수사·감사 중 원본 로그의 보존자와 접근자를 기록합니다.
