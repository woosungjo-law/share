서버에서 해킹 흔적을 발견했을 때

적용 상황: 운영 서버·관리자 페이지·계정 로그에서 비정상 접근 흔적을 발견했고, 아직 시스템을 만질지 말지 결정하지 못한 상태입니다.

Must Know · 알아야 할 것

  • 복구가 급해도 원본 상태 보존이 먼저입니다. 재부팅·종료·백신 실행은 메모리에 남은 흔적을 지우고 로그의 접근 시각을 바꿉니다.
  • 로그를 열어보는 것만으로도 메타데이터가 바뀔 수 있습니다. 확보 전에는 읽기만 하고, 누가 언제 무엇을 했는지 따로 적습니다.
  • 원인 규명을 서두른 내부 조사는 나중에 "증거를 손댔다"는 지적의 근거가 됩니다.

Must Check · 확인할 것

  • 최초 발견 시각·발견자·발견 경로(알림·로그·제보)를 적었는가
  • 영향받은 시스템·계정·조회 시도 대상의 범위를 목록으로 만들었는가
  • 발견 후 누가 어떤 조치를 했는지 시간순으로 남겼는가
  • 외부 분석 창구(업체 후보·계약 방식·연락 체계)를 확인했는가
  • 보고선과 의사결정권자(정보보호 책임자·법무·경영진)를 특정했는가
  • 원본 매체·백업본의 보관 위치와 접근 권한을 확인했는가

Must Do · 실행할 것

  1. 침해 의심 시스템의 외부 접근을 차단하고 네트워크에서 분리합니다. 전원은 끄지 않고 그대로 둡니다.
  2. 발견 시각부터 현재까지의 상황(발견자·시스템 상태·내린 조치·조치자)을 시간순으로 기록합니다.
  3. 추가 접속이 필요하면 승인자·목적·명령·결과를 남기는 형태로만 허용하고, 접속 인원과 횟수를 최소화합니다.
  4. 외부 분석 업체 선임 여부를 의사결정권자에게 올리고, 위임 범위·기간·산출물을 문서로 정합니다.
  5. 원본 매체는 쓰기 방지 상태로 이미징하고 원본·사본 해시값과 취급 기록을 함께 보관합니다. 원본은 봉인해 접근 통제 장소에 둡니다.
  6. 확보·분석 결과와 미확인 사항을 구분해 법무·경영진에 보고하고, 신고·통지 판단은 그 검토에 넘깁니다.
  7. 대외 문의·자료 요청은 지정 창구로 모으고, 응답 전에 사실관계 확인 절차를 거칩니다.
